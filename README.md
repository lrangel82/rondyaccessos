CONTEXTO ARQUITECTÓNICO COMPLETO DEL PROYECTO:
1. CAPA DE DATOS UNIFICADA (DataRawRondin.kt): Solución Offline-First compacta sin extensiones externas. Usa RAM (TableState), persistencia en disco con Strings JSON (MySettings) y Sincronización asíncrona con Google Sheets (Service Account en res/raw/). Cuenta con Mutex/Locks para control de concurrencia atómica.
2. ENUMS DE HARDWARE Y OPERACIÓN (SheetTable): Catálogos expandidos de condominio (VEHICULOS, TAGS, DIRECCIONES, AUTOS_REGISTRADOS, RESIDENTES_UNIDAD, ALARMAS_RONDIN, BITACORA_ACCESOS, EXCEPCIONES, DOMICILIOS_MOROSOS, TERRAZA_RESERVAS, PLACAS_PROHIBIDAS). Enum de roles físicos de hardware 'SateliteMode' (CASETA, INGRESO_VEHICULAR, INGRESO_PEATONAL, SALIDA_VEHICULAR, SALIDA_PEATONAL) alojados en el paquete core 'com.larangel.rondy.models'.
3. RED LOCAL DISTRIBUIDA (Ktor Sockets): Puerto 35420. RondySocketService (Foreground Service central en Caseta Padre) que corre un TCP Server para recibir JSONs y un UDP Broadcast para responder Discovery Pings usando .hostname. Los Satélites usan RondySocketClient para autodescubrimiento y envío síncrono.
4. LICENCIAMIENTO S3 Y SPLASH: SplashActivity descarga y valida un archivo .ini desde Amazon S3 usando OkHttpClient y XmlPullParser. Si el campo 'CODIGO_ACTIVACION' está vacío, implementa una corrutina suspendida (mostrarDialogoCapturaHKey) para pedirlo por un AlertDialog nativo y guardarlo antes de consultar S3. Si falla, rutea a LimitedFeatureActivity (Modo inactivo sin licencia que solo permite ver el Catálogo de Domicilios base y Bitácora local).
5. INYECCIÓN DE DEPENDENCIAS DE ALTO NIVEL (RondyApplication): Los objetos 'DataRawRondin' y 'GeminiVoiceAssistant' se instancian mediante el patrón 'by lazy' en la clase Application. Para consumirlos de forma segura en las pantallas protegiendo el ciclo de vida, se inyectan a los constructores de los ViewModels mediante una factoría personalizada obligatoria:
   "private val viewModel: IngresoVehicularViewModel by viewModels { IngresoVehicularViewModelFactory(application as RondyApplication) }"
   Cuenta con un puntero de callback dinámico ('registroCallbackActivo') en la Application para que el ViewModel de la pantalla activa intercepte los datos extraídos por la IA en tiempo de ejecución.
6. REDISEÑO MODULAR RECIENTE DEL SATÉLITE VEHICULAR (IngresoVehicularActivity):
   - Flujo Guiado Seccional: Controlado por un enum de pasos 'CaptureStep' (SELECCION_MOTIVO, SELECCION_CALLE, SELECCION_NUMERO, CAPTURA_NOMBRE, CAPTURA_PLACA, PROCESANDO_AUTORIZACION).
   - Inyección Dinámica de Chips: Los botones se cargan desde el JSON 'tiporegistro' en el .ini de S3 para los motivos, y desde las listas de DataRawRondin para las direcciones.
   - Solución de Bloqueo ANR Táctil: El 'ChipGroup.removeAllViews()' se protegió mediante la bandera estructural 'ultimoPasoProcesado != state.currentStep' para que solo se redibujen los botones si el paso cambia físicamente, evitando secuestros de la Input Queue táctil.
   - Control de Audio e Inteligencia Híbrida: Implementa 'SpeechRecognizer' nativo. Los hilos de filtrado se delegaron a 'Dispatchers.Default'. Se configuró 'controlarEstadoMicrofono()' para apagar el micrófono al hacer clics físicos y apagarlo por completo durante los pasos de teclado manual (Nombre y Placas).
   - Filtro de Conteo de Palabras por Voz: Al recibir el texto dictado, si el número de palabras es exactamente 1, la app asume un comando directo o selección de botón en pantalla, evadiendo la API de Gemini en la nube para procesar la lógica de inmediato mediante el emparejador local 'procesarEntradaVozLocalFallback' de forma 100% offline.
   - Temporizador de Pánico: Cuenta regresiva asíncrona de 30 segundos ('iniciarTimerInactividad()') controlada por un 'Job' que resetea la app al paso 1 por abandono. Se refresca de forma nativa mediante 'onUserInteraction()'.
   - Regularización Exprés: Excepciones inmediatas para Policía, Camión de Basura y Ambulancia que inyectan por default la calle 'Administracion' con número '1' para abrir la barrera al instante.
   - Conexión con Sockets y WhatsApp: Enlace directo al finalizar datos para sondeo paralelo (Polling) a la API de WhatsApp en Render (validar_visita).
7. PIPELINE EXTENDIDO DE DOBLE CÁMARA CONCURRENTES (LibVLC + CameraX):
   - Cámara IP Externa de Placas: Decodificada a través de 'LibVLC para Android' pasando el string URL directo a la clase 'Media' con aceleración por hardware. Para extraer los fotogramas sin bloquear la UI ni depender de archivos temporales en disco, se utiliza la API 'PixelCopy' que clona de forma asíncrona la textura de la GPU ('SurfaceView' hijo interno de 'VLCVideoLayout') cada 800ms y la pasa al analizador local de 'ML Kit Text Recognition' filtrado por un Regex alfanumérico. El stream de red se apaga por completo al obtener la matrícula para liberar ancho de banda.
   - Cámara Frontal para códigos QR: Inicializada de forma nativa con 'CameraX' conectando un caso de uso 'Preview' al 'PreviewView' del XML y un 'ImageAnalysis' (con estrategia STRATEGY_KEEP_ONLY_LATEST) hacia 'ML Kit Barcode Scanning'. Cuenta con un enfriamiento ('qrCooldownActivo') de 10 segundos tras detectar un QR condominal válido que comience con el prefijo "ginn".
   - Capa de Reconfiguración en Falla: Ambos cuadrantes de cámara cuentan con un overlay layout oculto ('gone') en el XML que se activa si el stream de red colapsa, permitiendo al vigilante reconfigurar URLs RTSP o conmutar hardware en caliente.
8. FILTRADO INTELIGENTE DE DIRECCIONES (Fuzzy & Ambigüedad de Gemini):
   - Al procesar la voz con "dataRawRondin.getDomicliosSimilares(calle, numero)", si se detecta una coincidencia exacta (size == 1), la app avanza a Nombre.
   - Si existen múltiples opciones (size > 1), el ViewModel concatena una cadena dinámica formateada en "calle:numero" en el 'lblTopMensaje', fuerza el 'currentStep' de vuelta a 'CaptureStep.SELECCION_CALLE' y actualiza la lista reducida en 'listaDomiciliosFiltrados' para obligar al ChipGroup a inyectar únicamente como botones las alternativas sobrevivientes del filtro de Gemini.
9. BACKGROUND SYNC SERVICE: Implementado con WorkManager (RondySyncWorker y SyncManager) bajo restricciones nativas de red (CONNECTED) y Backoff exponencial usando 'WorkRequest.MIN_BACKOFF_MILLIS' para vaciar de fondo las colas de DataRawRondin.
