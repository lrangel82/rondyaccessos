CONTEXTO ARQUITECTÓNICO COMPLETO DEL PROYECTO:
1. CAPA DE DATOS UNIFICADA (DataRawRondin.kt): Solución Offline-First compacta sin extensiones externas. Usa RAM (TableState), persistencia en disco con Strings JSON (MySettings) y Sincronización asíncrona con Google Sheets (Service Account en res/raw/). Cuenta con Mutex/Locks para control de concurrencia atómica.
2. ENUMS DE HARDWARE Y OPERACIÓN (SheetTable): Catálogos expandidos de condominio (VEHICULOS, TAGS, DIRECCIONES, AUTOS_REGISTRADOS, RESIDENTES_UNIDAD, ALARMAS_RONDIN, BITACORA_ACCESOS, EXCEPCIONES, DOMICILIOS_MOROSOS, TERRAZA_RESERVAS, PLACAS_PROHIBIDAS). Enum de roles físicos de hardware 'SateliteMode' (CASETA, INGRESO_VEHICULAR, INGRESO_PEATONAL, SALIDA_VEHICULAR, SALIDA_PEATONAL) alojados en el paquete core 'com.larangel.rondy.models'.
3. RED LOCAL DISTRIBUIDA (Ktor Sockets): Puerto 35420. RondySocketService (Foreground Service central en Caseta Padre) que corre un TCP Server para recibir JSONs y un UDP Broadcast para responder Discovery Pings usando .hostname. Los Satélites usan RondySocketClient para autodescubrimiento y envío síncrono.
4. LICENCIAMIENTO S3 Y SPLASH: SplashActivity descarga y valida un archivo .ini desde Amazon S3 usando OkHttpClient y XmlPullParser. Si el campo 'CODIGO_ACTIVACION' está vacío, implementa una corrutina suspendida (mostrarDialogoCapturaHKey) para pedirlo por un AlertDialog nativo y guardarlo antes de consultar S3. Si falla, rutea a LimitedFeatureActivity (Modo inactivo sin licencia que solo permite ver el Catálogo de Domicilios base y Bitácora local).
5. INYECCIÓN DE DEPENDENCIAS DE ALTO NIVEL (RondyApplication): Los objetos 'DataRawRondin' y 'GeminiVoiceAssistant' se instancian mediante el patrón 'by lazy' en la clase Application. Para consumirlos de forma segura en las pantallas protegiendo el ciclo de vida, se inyectan a los constructores de los ViewModels mediante una factoría personalizada obligatoria:
   "private val viewModel: IngresoVehicularViewModel by viewModels { IngresoVehicularViewModelFactory(application as RondyApplication) }"
   Cuenta con un puntero de callback dinámico ('registroCallbackActivo') en la Application para que el ViewModel de la pantalla activa intercepte los datos extraídos por la IA en tiempo de ejecución. Ambas dependencias consumen la configuración de MySettings en caliente, inicializada dinámicamente tras pasar el Splash de S3.
6. REDISEÑO MODULAR RECIENTE DEL SATÉLITE VEHICULAR (IngresoVehicularActivity):
   - Flujo Guiado Seccional: Controlado por un enum de pasos 'CaptureStep' (SELECCION_MOTIVO, SELECCION_CALLE, SELECCION_NUMERO, CAPTURA_NOMBRE, CAPTURA_PLACA, PROCESANDO_AUTORIZACION).
   - Inyección Dinámica de Chips: Los botones se cargan desde el JSON 'tiporegistro' en el .ini de S3 para los motivos, y desde las listas de DataRawRondin para las direcciones.
   - Solución de Bloqueo ANR Táctil: El 'ChipGroup.removeAllViews()' se protegió mediante la bandera estructural 'ultimoPasoProcesado != state.currentStep' para que solo se redibujen los botones si el paso cambia físicamente, evitando la sobreescritura y secuestro de la Input Queue táctil de Android.
   - Control de Audio e Inteligencia Híbrida Avanzada: Implementa 'SpeechRecognizer' nativo. Los hilos de filtrado se delegaron a 'Dispatchers.Default'. Se configuró 'controlarEstadoMicrofono()' para apagar el micrófono al hacer clics físicos y desactivarlo por completo durante los pasos de teclado manual (Nombre y Placas) liberando el búfer de entrada del sistema al 100%.
   - Forzado de Localización en Español (es-MX): El SpeechRecognizer se blindó forzando 'es-MX' en EXTRA_LANGUAGE, EXTRA_LANGUAGE_PREFERENCE y EXTRA_ONLY_RETURN_LANGUAGE_PREFERENCE, anulando configuraciones inglesas de fábrica por defecto de ROMs o emuladores.
   - Filtro de Conteo de Palabras por Voz: Al recibir texto dictado, si el número de palabras separadas por espacios es exactamente 1 (evaluado con Regex "\\s+"), la app asume un comando directo o selección de botón en pantalla, evadiendo por completo la llamada asíncrona de la API de Gemini en la nube para procesar de inmediato el emparejamiento con el catálogo local 'procesarEntradaVozLocalFallback' de forma 100% offline.
   - Temporizador de Pánico: Cuenta regresiva asíncrona de 30 segundos ('iniciarTimerInactividad()') controlada por un 'Job' que resetea la app al paso 1 por abandono. Se refresca de forma nativa mediante 'onUserInteraction()'.
   - Regularización Exprés: Excepciones inmediatas para Policía, Camión de Basura y Ambulancia que inyectan por default la calle 'Administracion' con número '1' para abrir la barrera al instante sin requerir cuestionarios.
   - Conexión con Sockets y WhatsApp: Enlace directo al finalizar datos para sondeo paralelo (Polling) a la API de WhatsApp en Render (validar_visita).
7. PIPELINE EXTENDIDO DE DOBLE CÁMARA CONCURRENTES (LibVLC + CameraX):
   - Cámara IP Externa de Placas: Decodificada a través de 'LibVLC para Android' pasando el string URL directo a la clase 'Media' con aceleración por hardware. Para extraer los fotogramas sin bloquear la UI ni depender de archivos temporales en disco, se utiliza la API 'PixelCopy' que clona de forma asíncrona la textura de la GPU ('SurfaceView' hijo interno de 'VLCVideoLayout') cada 800ms en el pool de background y la pasa al analizador local de 'ML Kit Text Recognition' filtrado por un Regex alfanumérico. El stream de red se apaga por completo al obtener la matrícula para liberar recursos y ancho de banda.
   - Cámara Frontal para códigos QR: Inicializada de forma nativa con 'CameraX' conectando un caso de uso 'Preview' al 'PreviewView' del XML y un 'ImageAnalysis' (con estrategia STRATEGY_KEEP_ONLY_LATEST) hacia 'ML Kit Barcode Scanning'. Cuenta con un enfriamiento ('qrCooldownActivo') de 10 segundos tras detectar un QR condominal válido que comience con el prefijo "ginn".
   - Solución a Pantallas en Negro (TextureView & Croma VLC): Para evitar que LibVLC secuestre de forma exclusiva el plano de la GPU solapando la previsualización del QR, se forzó en el XML de CameraX 'app:implementationMode="compatible"' (TextureView), se agregaron los argumentos de inicialización nativos en LibVLC '--vout=android_display', '--android-display-chroma=RV32', '--video-wallpaper' y se automatizó el permiso dinámico de hardware mediante un contrato nativo de Jetpack ('ActivityResultContracts.RequestPermission()') enganchado al flujo seguro '.post {}' de la Activity.
   - Manejo Asíncrono de Errores de Red en Cámara IP (Contingencia en Falla): Dado que las fallas por IPs inválidas de RTSP corren en el core de C++ de VLC y no saltan en los try-catch de Kotlin, se implementó un 'mediaPlayer.setEventListener' interceptando 'Event.EncounteredError' junto con un coroutine timeout de pánico de 5 segundos. Si la conexión colapsa o expira el tiempo, la app apaga el canal y activa de inmediato un panel gris translúcido ('layoutFixCamaraPlaca') en ese cuadrante para que el guardia reconfigure URLs o conmute hardware en caliente.
8. MANEJO DE SEÑALES ACÚSTICAS E INTERRUPCIÓN HÍBRIDA (TTS Audio Focus):
   - Para eliminar el ruido de golpeteo (chasquidos pop) en el altavoz, se espaciaron los ciclos de reinicios de hardware a 2000ms.
   - Para resolver la anulación silenciosa de las bocinas cuando el micrófono secuestra el Audio Focus en modo grabación, se dotó a GeminiVoiceAssistant de un método 'setTtsProgressListener' expuesto públicamente. Al implementarse un 'UtteranceProgressListener' atado al ID "RondySpeechID" (forzado en el método tts.speak), la Activity apaga automáticamente el micrófono en 'onStart()' de la locución de la IA y lo reenciende en el evento 'onDone()', permitiendo que las instrucciones del altavoz se escuchen fuerte y claro.
9. PANEL DE INSTRUMENTACIÓN VISUAL DE HARDWARE POR COLORES:
   - Se inyectó en el encabezado superior un círculo dinámico ('indicadorColorMicro') que muta mediante 'runOnUiThread' informando el estado exacto del búfer de audio en tiempo real para agilizar diagnósticos: VERDE (Escuchando), AZUL (Captando Voz), AMARILLO (Procesando), MORADO (Asistente Hablando por el altavoz), GRIS (Teclado manual activo de contingencia).
10. FILTRADO INTELIGENTE DE DIRECCIONES (Fuzzy & Ambigüedad de Gemini):
- Al procesar la voz con "dataRawRondin.getDomicliosSimilares(calle, numero)", si se detecta una coincidencia exacta (size == 1), la app avanza a Nombre.
- Si existen múltiples opciones (size > 1), el ViewModel concatena una cadena dinámica formateada en "calle:numero" en el 'lblTopMensaje', fuerza el 'currentStep' de vuelta a 'CaptureStep.SELECCION_CALLE' y actualiza la lista reducida en 'listaDomiciliosFiltrados' para obligar al ChipGroup a inyectar únicamente como botones las alternativas sobrevivientes del filtro de Gemini, optimizando el Modo Híbrido.
11. PARSING DE GEMINI RESILIENTE (application/json):
   - Se agregó el flag obligatorio 'responseMimeType = "application/json"' dentro del bloque 'generationConfig' de Gemini para forzar la salida JSON nativa sin bloques de código Markdown. Se embebió una expresión regular de descarte preventivo ('replace("```json", "")') ante cualquier variación del servidor.
12. BACKGROUND SYNC SERVICE: Implementado con WorkManager (RondySyncWorker y SyncManager) bajo restricciones nativas de red (CONNECTED) y Backoff exponencial usando 'WorkRequest.MIN_BACKOFF_MILLIS' para vaciar de fondo las colas de DataRawRondin.

13. ENUMS ENRIQUECIDOS (SheetTable): Catálogo unificado y centralizado con propiedades estructurales dinámicas. Cada tabla (incluyendo las nuevas como BITACORA_ACCESOS, RESIDENTES_UNIDAD, PARKING_SLOTS, etc.) controla su 'sheetName' (mutable vía MySettings para renombrado en producción), 'cacheKey', 'range' personalizado y 'headers' oficiales de Google Sheets (Single Source of Truth). Posee getters calculados para llaves de persistencia (saveKey, timestampKey).
14. INFRAESTRUCTURA OFFLINE-FIRST (DataRawRondin):
   - createWorkSheetNew(spreadsheetId, table): Método genérico que realiza un BatchUpdate estructural si la pestaña remota no existe en Google Sheets, inyectando preventivamente la fila de cabeceras ('table.headers') en el rango A1 bajo Dispatchers.IO y Mutex de exclusión mutua.
   - addBitacoraAccesos(AccesoBitacora): Recibe una entidad fuertemente tipada de 13 columnas. Ejecuta una estrategia 'Optimistic UI' impactando inmediatamente la memoria RAM (TableState), persistiendo localmente en disco como JSON string en MySettings y encolando de forma asíncrona no bloqueante el push a la nube vía sync(table, Operation.APPEND).
15. PIPELINE DE AUTORIZACIÓN POR WHATSAPP (ViewModel e Interfaz de Red):
   - Lógica de Sondeo (Polling Loop): Implementada en IngresoVehicularViewModel usando corrutinas vinculadas a viewModelScope. Extrae los teléfonos de residentes válidos de una dirección vía DataRawRondin.obtenerTelefonosPorDireccion().
   - Consumo de API (BotCasetaApiService): Realiza llamadas POST secuenciales a la API en Render (validar_visita) cada 3 segundos, blindada con validación temporal estricta de 5 minutos máximos de antigüedad analizando estampas de tiempo ISO-8601 UTC mediante 'Instant.parse()'.
   - Retransmisión y Cierre: Si detecta 'visita_acceso_permitido' o 'visita_acceso_denegado', invoca la función en segundo plano 'informar_respuesta_visita' hacia el resto de los copropietarios, interrumpe el bucle de red y despacha la transacción hacia 'ejecutarGuardadoTransaccionalFinal(state)'.
   - Método 'cancelarSolicitudManual()': Detiene de manera instantánea todos los hilos de sondeo (pollingJob) y de tiempo (timerJob) liberando los recursos de red del sistema si el guardia aborta la operación.
16. COMPONENTE REACTIVO DE DIÁLOGO (IngresoVehicularActivity):
   - Escucha reactiva ligada al flujo 'whatsappStatus' mediante la API segura 'repeatOnLifecycle(Lifecycle.State.STARTED)'.
   - Administra un único AlertDialog nativo inflado desde 'dialog_whatsapp_auth.xml' que actualiza dinámicamente sus textos en caliente (Html.fromHtml para destacar campos en negrita) y muta sus estilos y colores por runOnUiThread según el estado final (Verde=Autorizado, Rojo=Denegado, Naranja=Timeout).
   - Acopla el evento onClick del botón cancelar directamente a la función de aborto del ViewModel.
