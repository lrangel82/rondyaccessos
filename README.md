CONTEXTO ARQUITECTÓNICO COMPLETO DEL PROYECTO:
1. CAPA DE DATOS UNIFICADA (DataRawRondin.kt): Solución Offline-First compacta sin extensiones externas. Usa RAM (TableState), persistencia en disco con Strings JSON (MySettings) y sincronización asíncrona con Google Sheets (Service Account en res/raw/). Cuenta con Mutex/Locks para control de concurrencia atómica.
2. ENUMS DE HARDWARE Y OPERACIÓN (SheetTable): Catálogos expandidos de condominio (VEHICULOS, TAGS, DIRECCIONES, AUTOS_REGISTRADOS, RESIDENTES_UNIDAD, ALARMAS_RONDIN, BITACORA_ACCESOS, EXCEPCIONES, DOMICILIOS_MOROSOS, TERRAZA_RESERVAS, PLACAS_PROHIBIDAS). Enum de roles físicos de hardware 'SateliteMode' (CASETA, INGRESO_VEHICULAR, INGRESO_PEATONAL, SALIDA_VEHICULAR, SALIDA_PEATONAL) alojados en el paquete core 'com.larangel.rondy.models'.
3. RED LOCAL DISTRIBUIDA (Ktor Sockets): Puerto 35420. RondySocketService (Foreground Service central en Caseta Padre) que corre un TCP Server para recibir JSONs y un UDP Broadcast para responder Discovery Pings usando .hostname. Los Satélites usan RondySocketClient para autodescubrimiento y envío síncrono.
4. LICENCIAMIENTO S3 Y SPLASH: SplashActivity descarga y valida un archivo .ini desde Amazon S3 usando OkHttpClient y XmlPullParser. Si el campo 'CODIGO_ACTIVACION' está vacío, implementa una corrutina suspendida (mostrarDialogoCapturaHKey) para pedirlo por un AlertDialog nativo y guardarlo antes de consultar S3. Si falla, rutea a LimitedFeatureActivity (Modo inactivo sin licencia que solo permite ver el Catálogo de Domicilios base y Bitácora local).
5. INYECCIÓN DE DEPENDENCIAS DE ALTO NIVEL (RondyApplication): Los objetos 'DataRawRondin' y 'GeminiVoiceAssistant' se instancian mediante el patrón 'by lazy' en la clase Application. Para consumirlos de forma segura en las pantallas protegiendo el ciclo de vida, se inyectan a los constructores de los ViewModels mediante una factoría personalizada ('IngresoVehicularViewModelFactory').
6. REDISEÑO MODULAR RECIENTE DEL SATÉLITE VEHICULAR (IngresoVehicularActivity):
   - Flujo Guiado Seccional: Controlado por un enum de pasos 'CaptureStep' (SELECCION_MOTIVO, SELECCION_CALLE, SELECCION_NUMERO, CAPTURA_NOMBRE, CAPTURA_PLACA, PROCESANDO_AUTORIZACION).
   - Inyección Dinámica de Chips: Los botones se cargan desde el JSON 'tiporegistro' en el .ini de S3 para los motivos, y desde las listas de DataRawRondin para las direcciones.
   - Solución de Bloqueo ANR Táctil: Para evitar que el micrófono secuestre los clics o recree los botones en bucle infinito borrando la Input Queue, el 'ChipGroup.removeAllViews()' se protegió mediante una bandera de control estructural ('ultimoPasoProcesado != state.currentStep') para que solo se redibujen si el paso cambia físicamente.
   - Control de Audio Inteligente: Implementa 'SpeechRecognizer' nativo. Los hilos pesados de filtrado de strings se delegaron a 'Dispatchers.Default' en el ViewModel. Se configuró 'controlarEstadoMicrofono()' para apagar el micrófono temporalmente al hacer clics físicos y apagarlo por completo durante los pasos de captura por teclado (Nombre y Placas) para liberar el búfer táctil del sistema al 100%.
   - Temporizador de Pánico: Cuenta regresiva asíncrona de 30 segundos ('iniciarTimerInactividad()') controlada por un 'Job' que resetea la app al paso 1 por abandono. Se refresca de forma nativa mediante 'onUserInteraction()'.
   - Regularización Exprés: Excepciones inmediatas para Policía, Camión de Basura y Ambulancia que inyectan por default la calle 'Administracion' con número '1' para abrir la barrera al instante.
   - Conexión con Sockets y WhatsApp: Enlace directo al finalizar datos para sondeo paralelo (Polling) a la API de WhatsApp en Render (validar_visita).
7. CORRECCIÓN VITAL DE INICIALIZACIÓN DE LA ACTIVITY: Las Activities deben instanciar su ViewModel utilizando la fábrica formal para evitar errores de referencias nulas o hilos huérfanos. La sintaxis correcta obligatoria es:
   "private val viewModel: IngresoVehicularViewModel by viewModels { IngresoVehicularViewModelFactory(application as RondyApplication) }"
8. BACKGROUND SYNC SERVICE: Implementado con WorkManager (RondySyncWorker y SyncManager) bajo restricciones nativas de red (CONNECTED) y Backoff exponencial usando 'WorkRequest.MIN_BACKOFF_MILLIS' para vaciar de fondo las colas de DataRawRondin.
